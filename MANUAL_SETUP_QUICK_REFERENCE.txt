🔐 PART 2: Create GitHub OIDC Identity Provider

URL:       https://console.aws.amazon.com/iam/
Navigate:  Left sidebar → "Identity providers"
Click:     [Add provider] button (orange)

Configure:
  • Provider type:      OpenID Connect
  • Provider URL:       https://token.actions.githubusercontent.com
  • Audience:          sts.amazonaws.com
  • Get Thumbprint:    Click [Get thumbprint] button

Expected Result:
  ✅ Provider "token.actions.githubusercontent.com" appears in list
  ✅ Type: OpenID Connect

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

👤 PART 3: Create IAM Role

URL:       https://console.aws.amazon.com/iam/
Navigate:  Left sidebar → Roles
Click:     [Create role] button (orange)

Step 1 - Select Trusted Entity:
  • Trusted entity type:  Web identity
  • Identity provider:    token.actions.githubusercontent.com
  • Audience:            sts.amazonaws.com
  • Click:               [Next]

Step 2 - Add Permissions:
  • Search for:         AdministratorAccess
  • Check:              The checkbox next to it
  • Click:              [Next]

Step 3 - Name Role:
  • Role name:          GitHubActionsADRDeployRole (exactly!)
  • Description:        Role for GitHub Actions to deploy ADR Scanner to AWS
  • Click:              [Create role]

Expected Result:
  ✅ Green success message
  ✅ Role "GitHubActionsADRDeployRole" created

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔑 PART 4: Edit Trust Policy (MOST IMPORTANT!)

URL:       https://console.aws.amazon.com/iam/
Navigate:  Left sidebar → Roles
Find:      GitHubActionsADRDeployRole
Click:     Trust relationships tab
Click:     [Edit trust policy] button

IMPORTANT: Replace YOUR_ACCOUNT_ID with your Account ID!

Delete:    ALL existing JSON in editor

Replace with:
─────────────────────────────────────────────────────────────────────
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::YOUR_ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo:anoopmc1981/AI-Project-ADR:*"
        }
      }
    }
  ]
}
─────────────────────────────────────────────────────────────────────

Click:     [Update policy]

Expected Result:
  ✅ Green success message
  ✅ Trust policy updated with TWO conditions

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🚨 COMMON MISTAKES

❌ Account ID Typo
   → Always use 12 digits from AWS Console top-right
   → Don't guess or make up numbers

❌ Trust Policy Not Fully Updated
   → Must have TWO Condition blocks (Audience + Repository)
   → Not just one condition
   → Copy/paste exact JSON from guide

❌ GitHub Secret Has Extra Spaces
   → No spaces before "arn:"
   → No spaces after the role name
   → Exact match to Role ARN

❌ Missing "id-token: write" in Workflow
   → This is REQUIRED for OIDC
   → Without it, no token is generated
   → GitHub Actions will fail

❌ Wrong Repository Name
   → Must be: anoopmc1981/AI-Project-ADR
   → Not: AI-Project-ADR
   → Not: anoopmc1981/adr-scanner
   → Exactly as shown

📞 QUICK TROUBLESHOOTING

Error: "Not authorized to perform sts:AssumeRoleWithWebIdentity"
  FIX: Trust policy is wrong. Re-read Part 4 carefully.
       Make sure you have TWO conditions.

Error: "Credentials could not be loaded"
  FIX: GitHub secret wrong or not updated. 
       Verify AWS_IAM_ROLE secret has correct Role ARN.
       Wait 1 minute and re-run workflow.

Error: "Role does not exist"
  FIX: Role name is spelled wrong or not created.
       Go to AWS IAM Roles, search for exact name.
       Create it again if missing.

Workflow doesn't generate OIDC token
  FIX: Missing "id-token: write" in workflow permissions.
       Add it to .github/workflows/deploy.yml
